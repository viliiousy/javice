# Bashy 안드로이드 출시 안내

앱 패키지 이름은 `app.bashy`(아이폰과 같음)입니다. 빌드는 GitHub Actions의 **Android app** 워크플로가 합니다. 맥미니는 업로드 키를 처음 한 번 만들 때만 씁니다.

| 이미 되어 있는 것 | 직접 하실 것 |
|---|---|
| 안드로이드 빌드: 위젯 2종, 구글 로그인, 알림, 진동, 음성 | 플레이 콘솔 가입 |
| 업로드 키 생성 스크립트 | 업로드 키 만들기 (명령 1줄) |
| 스토어용 이미지 (`docs/playstore/`) | 구글 클라우드에 안드로이드 로그인 클라이언트 등록 |
| 계정 삭제 안내 페이지 (bashy.app/delete-account.html) | 스토어 등록정보·앱 콘텐츠 입력, 테스트, 출시 |

---

## 1. 플레이 콘솔 가입

- 가입 주소: https://play.google.com/console
- 등록비 25달러를 한 번 냅니다. 신분 확인도 거칩니다.
- **개인 계정은 바로 정식 출시가 되지 않습니다.** 2023년 11월 13일 이후 만든 개인 계정은 먼저 비공개 테스트를 거쳐야 합니다.
  - 테스터 12명 이상이 14일 연속 참여해야 합니다.
  - 그다음 '프로덕션 액세스 신청'을 할 수 있습니다.
  - 근거: [Play 콘솔 고객센터](https://support.google.com/googleplay/android-developer/answer/14151465)
- 조직(사업자) 계정은 D-U-N-S 번호가 필요하지만 이 테스트 요건이 없습니다(확인 필요).

## 2. 업로드 키 만들기 (맥미니에서 한 번)

```
cd ~ && git -C bashy-ios pull -q && bash bashy-ios/app/scripts/android-key.sh
```

이 스크립트가 하는 일:

- 키 파일을 `~/BashyKeys/bashy-upload.jks`에 만듭니다. 비밀번호는 같은 폴더의 `password.txt`에만 적습니다.
- GitHub 저장소 비밀값 4개를 넣습니다: `ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
- 마지막에 **SHA-1**을 보여 줍니다. 3단계에서 씁니다.

필요한 것이 없으면 스크립트가 알려 줍니다:

- 자바: `brew install --cask temurin`
- GitHub CLI: `brew install gh && gh auth login`

`~/BashyKeys` 폴더는 따로 백업해 두세요. 잃어버려도 플레이 콘솔에서 '업로드 키 재설정'을 요청할 수 있지만 며칠 걸립니다.

## 3. 구글 로그인 (안드로이드 클라이언트 등록)

안드로이드 앱은 기존 **웹 클라이언트 ID**를 그대로 씁니다. 코드는 이미 그렇게 되어 있습니다. 다만 구글이 "이 앱이 진짜 Bashy인가"를 서명으로 확인하므로, 구글 클라우드에 **Android 유형 OAuth 클라이언트**를 추가해야 합니다.

1. 웹 클라이언트가 있는 구글 클라우드 프로젝트를 엽니다.
2. API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID → **Android**를 고릅니다.
3. 패키지 이름에 `app.bashy`, SHA-1에 아래 값을 넣습니다. 서명 키마다 하나씩 만듭니다.

| 용도 | SHA-1 |
|---|---|
| 테스트 APK (워크플로의 고정 디버그 키) | `18:23:53:62:B6:77:1A:90:23:64:8B:1A:E2:30:80:5D:96:77:4C:64` |
| 업로드 키 | 2단계 스크립트가 보여 준 값 |
| **Play 앱 서명 키** (스토어에서 받은 앱은 이 키로 서명됨) | 플레이 콘솔 → 앱 → 테스트 및 출시 → 설정 → 앱 서명 |

OAuth 동의 화면이 아직 '확인 전' 상태이면 아이폰과 마찬가지로 100명 제한과 '확인되지 않은 앱' 경고가 그대로 적용됩니다.

## 4. (선택) 서버 푸시

- 앱 안의 알림(습관·식단·할일·일정)은 **기기 안에서 예약**되므로 이 단계 없이도 울립니다.
- 서버 푸시(FCM)도 쓰려면 다음을 합니다.
  1. Firebase 콘솔 → 프로젝트 설정 → 앱 추가 → Android(`app.bashy`)를 등록합니다.
  2. `google-services.json`을 받습니다.
  3. 파일 내용 전체를 저장소 비밀값 `GOOGLE_SERVICES_JSON`에 넣습니다.

## 5. 빌드

1. GitHub → Actions → **Android app** → Run workflow를 누릅니다.
2. 끝나면 실행 화면 아래 **Artifacts**에서 `bashy-android-<번호>`를 받습니다.

| 파일 | 용도 |
|---|---|
| `bashy.aab` | 플레이 콘솔에 올리는 파일 (업로드 키가 있을 때) |
| `bashy.apk` / `bashy-debug.apk` | 휴대폰에 바로 깔아 보는 파일 |

- 버전 이름은 `app/package.json`의 `version`을 따릅니다. 버전 코드는 빌드 시각에서 자동으로 올라갑니다.
- 워크플로 요약 화면에 그 빌드의 SHA-1이 찍힙니다.
- (선택) 플레이 콘솔 API 서비스 계정 JSON을 비밀값 `PLAY_SERVICE_ACCOUNT_JSON`에 넣으면, Run workflow 때 고른 트랙(internal/alpha)에 **초안**으로 자동으로 올라갑니다.

## 7. 테스트 → 출시

1. 테스트 및 출시 → **비공개 테스트**에서 트랙을 만들고 `bashy.aab`를 올립니다.
2. 테스터 이메일 12명 이상을 넣고, 참여 링크를 보내 14일 동안 유지합니다(개인 계정).
3. 대시보드에서 **프로덕션 액세스 신청**을 합니다.
4. 승인되면 프로덕션 트랙에 같은 빌드를 올려 출시합니다.

이후 업데이트는 `app/package.json` 버전을 올리고 Run workflow를 다시 누른 뒤, 새 `bashy.aab`를 올리면 됩니다. 화면만 바뀐 업데이트도 앱 안의 웹 화면이 번들에 들어 있으므로 새 빌드가 필요합니다. 아이폰과 같습니다.

## 위젯

**안드로이드 위젯** (홈 화면 길게 누르기 → 위젯 → Bashy)

| 위젯 | 크기 | 보여 주는 것 |
|---|---|---|
| Bashy 오늘 | 4×2 | 습관 진행(크게), 할 일 3개, 다음 일정, 체크·남은 칼로리·몸무게 |
| Bashy 습관 | 2×2 | 습관 진행과 다음 습관 |

- 위젯은 앱이 열려 있을 때 넘겨 준 '오늘 요약'을 그립니다.
- 날짜가 바뀌었는데 앱을 아직 열지 않았으면 어제 숫자 대신 '앱을 한 번 열면 오늘 요약이 채워집니다'를 보여 줍니다.

**아이폰 위젯**: 같은 디자인으로 작은 크기와 중간 크기를 만들었습니다. 다음 버전(1.0.2)에 들어갑니다.
